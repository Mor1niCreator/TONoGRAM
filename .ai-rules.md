# Gram vs Ton - Architecture & Performance Rules (.ai-rules.md)

## 1. Authoritative Server Architecture
- **State Sovereignty**: The server (`server/GameRoom.ts`) is the single source of truth for physics, positions, velocities, collisions, score, and powerups.
- **Client Prediction & Interpolation**: The client predicts its own mallet position for zero-latency feel but interpolates all other entities (puck, opponent mallet, powerups) based on a buffered series of server states.
- **Anti-Cheat Validation**: The server validates all client inputs (velocities, coordinates) to ensure mallets do not exceed speed limits, skip barriers, or cross the midline.

## 2. Network Traffic Optimization
- **Tick Rates & Sync Rates**: Physics tick rate is locked at 60Hz. Network state broadcast is throttled to 30Hz.
- **Input Throttling**: Client inputs must be throttled to prevent sending duplicate coordinates at rates higher than 60Hz.
- **Delta-Compression (Optional/Future)**: Only send changed values to conserve bandwidth over unstable mobile connections (3G/4G/5G).

## 3. Mobile Performance Guidelines
- **Low CPU Footprint**: Avoid garbage collection spikes by reusing Vector objects and physics body references.
- **Canvas API Rendering**: Optimize canvas redraws. Use minimal layers, batch operations, and avoid heavy styling recalculations in the render loop.
- **Interpolation Delay**: Buffer server packets and render at `t - 100ms` to guarantee smooth, jitter-free movement on unstable mobile connections.
